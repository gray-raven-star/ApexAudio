# 架构

## 责任边界

```
本地 WebView2 UI
    │ JSON 界面命令／状态
Desktop 宿主
    │
Application 工作台操作
    ├─ Core：包、预设、进程识别、IPC、录音
    └─ XHaptics：输入转送与只读震动遥测
    │ 控制管道＋二进制音频管道
游戏 Adapter 独立进程
    └─ 包内的具体采集实现／原生模块
```

支持 `realtimeMix` 的适配包另提供采集端混音共享缓冲区，X-Haptics 反馈模块直接消费它。分组选择由工作台通过控制管道下发；独立 PCM 管道供活动显示、录音与试听使用。反馈不等待宿主录音写盘。主程序按能力与格式选择路径，不按游戏名称、SDK 或引擎判断。未声明此能力的旧包继续使用通用宿主混音。

`Contracts` 不引用 UI、具体引擎或具体游戏。`Core` 不引用 Wwise、游戏文件格式或注入逻辑。`Windows` 是可选的内部进程调用辅助代码，只供需要它的适配器／反馈模块使用。

Desktop 不加载第三方适配器 DLL；只从已校验包启动 EXE。Adapter 崩溃关闭自己的管道，宿主停止会话、结束录音、关闭反馈，界面继续运行。独立进程不是安全沙箱。

首版同时连接一个游戏／适配器。多个匹配包或多个游戏实例存在时不自动猜测。包作者可以使用任何语言，只需遵循 IPC 协议。

## 用户数据

- `data/packs/<id>`：安装后的完整包；安装更新先校验暂存目录，再替换。
- `data/presets/<pack-id>`：用户副本，与作者原稿独立。
- `data/recordings/<session-id>`：独立 WAV 和 session.json。
- `data/trusted.json`：首次运行许可按清单摘要记录，更新包后重新确认。
- `data/settings.json`：端口、增益、自动连接偏好。
- `data/webview`：界面运行缓存。

源代码与这些运行数据分开，`dist`、`artifacts`、`bin`、`obj` 不属于源码。

## 状态与真实性

包清单只负责识别。Adapter 运行时报告采集能力；收到某组有效 PCM 后，本体才将其标记为“已收到独立音轨”。这只能证明收到符合协议的数据，无法从任意第三方程序输出自动证明声源语义真实；作者仍需保证独立音轨没有伪造。Mock 用不同波形验证运输与录音链路。

显示文件夹不改变实际混音层级。反馈选取依据实际父子路由：包含子组的父组被选择时，不再把其已选子组叠加。独立录制仍保留各组，可能存在真实的父子内容重叠。

包中的游戏版本规则与适配器二次核对共同生效。V1 不提供自动解包、运行时资源扫描、SDK 猜测、AI 或反作弊绕过。
