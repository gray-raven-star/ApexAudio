# 按数据链路排查

先按 [最小实验](first-probes.md)辨别假设、观察和证据。

每次只解决最早失败的一层。保留短报告，避免在没有新证据时反复录音、重启驱动、全盘扫描或搜索资料。

| 阶段／现象 | 检查 | 处理方法 |
|---|---|---|
| 缺编译器或依赖 | Setup 输出、随附 toolchain、.NET SDK 与 Runtime 的区别 | 使用随附路径或显式参数；把依赖写进环境说明，不能依赖维护者的缓存 |
| 没有识别引擎 | 检查范围、运行模块、配置、导出和资源头 | 保持未确认；区分静态链接、延迟加载和未知格式，不凭字符串缺失下结论 |
| 读到了分组，连不上 | 实际 SDK ABI、对象实例、必要接口和游戏摘要 | 资源读取与实时采集分开验证；扩展包内定位器／后端 |
| 访问拒绝 | 当前身份、进程权限、保护状态 | 使用允许的同等权限测试环境；受保护目标不绕过保护，明确报告权限缺口 |
| 后台或暂停时无声 | 前台状态、实际发声、音量和声源休眠 | 先恢复已知声源，保持短时观察；音频暂停不代表连接失效，不因一次空数据改 ABI |
| 注册成功但回调为零 | 是否只是请求入队、实际对象、虚表槽、生命周期、静音休眠 | 核对注册完成与真正调用者；按真实 ABI 测试，不靠模拟直接函数调用证明注册 |
| 有回调但有效 PCM 为零 | 输入参数、帧数、通道、采样率、缓冲格式 | 单独统计进入次数和每类拒绝原因，保存少量头部诊断；不能把拒绝数据当正常静音 |
| 内部非零，输出却静音 | 每轮开始／结束标记、清理次序、通道布局 | 在正确处理阶段复制、发布和重置，防止先清掉本轮有效标记 |
| 映射有数据但管道没有 | 头部 magic、块尺寸、读写位置、sequence、groupIndex 和过滤 | 核对生产者与消费者 ABI；避免重复跳过新块或把未登记索引静默丢弃 |
| 管道有数据但录音为空 | 实际收到帧、时间原点、轨道编号、录制窗口 | 校验 QPC 基准和第一帧时间，检查过早／过晚帧而非无条件补零 |
| 开始正常，过一会停止 | 任务状态、保活时间、回压、映射 active | 保活不等待 IPC 或写盘；用一次快照比较时钟，避免无符号减法下溢；真实停止上报而非一直显示采集中 |
| 反馈比声音迟 | 每段延迟与队列时长、时间戳、回调块长 | 分别量采集、转送和 DSP；反馈不经过录音写盘，丢弃过时积压；不靠改时间戳假装更实时 |
| 小声也有明显震动 | 包内 PCM 幅度、输入增益、驱动 DSP、原生与补充分量 | 分开观察各来源，空选择验证补充输入，不从听感推断马达强度 |
| 多个分组内容相同 | 实际父子路由、共享效果返回、独立 PCM 来源 | 父组可能包含子组；共享混响可含多类声源，命名不证明独立；选择时去重 |
| 更新仍像旧版 | 实际包版本、模块路径与摘要、进程是否仍载入旧 DLL | 正常停止后重开目标，使用可区分的新模块文件名；检查构建暂存目录是否混入旧产物 |
| 断开时卡住／退出报错 | 取消顺序、未结束回调、异步移除、正常管道结束 | 等待后台任务结束再释放映射；正常 Shutdown 不作为异常；不要强行卸载仍被调用的模块 |

## 建议计数

包后端应至少能在自身报告中区分：候选分组数、解析成功数、注册请求数、确认注册数、回调次数、拒绝格式次数、非零帧、已发布块、丢块和保活年龄。它们属于诊断能力，不必给主程序添加游戏专属分支。

通用 DevTools 能观察导出、协议、PCM、状态与公共反馈映射，不能替任意后端读取其私有计数；后端作者应提供附加诊断接口或只读报告，并写明字段。不要把“对象能找到”当作“监听已开始”。

## 共享音轨的边界

通道中已经混合的语音、音乐与音效不能通过改名或开关拆开。应寻找处理前更细的路由；没有细路由时如实说明。合成后的低频幅度、人耳听感和手柄 DSP 输出不是线性对应。

## 读懂零值，不误判兼容性

- 实时共享混音 blocks 增长：只证明生产者发布块，内容可能全零；不能直接写采集成功。
- packets / frames 为零：独立音频管道未收到数据，需继续查该分支；不能仅因实时混音存在就忽略。
- nonZeroGroups 大于零：证明测试场景收到相应轨道非零 PCM，不证明其他场景、名称或所有分组正确。
- 多组总帧数：累加包含重叠轨道，不能直接除采样率作为墙钟录音时长。
- 初始反馈开关全关闭：实时混音静音正常，但 StartCapture 请求的独立轨道仍应能录制。

没有反复重试的必要时，保留一次短报告交付。若要复查，说明新增条件，如游戏由后台切回前台，而不是无条件再录一次。

## 权限与临时目录

先运行 Setup，查看 .cache/tmp 等路径是否可写。DevTools 使用进程环境变量 APEX_AUDIO_TEMP，Setup 在自己的 PowerShell 进程设置的值不会反向传回父终端；若随后直接运行 exe，应在当前终端显式设置到可写本地目录，或让诊断工具使用系统可写临时目录。

沙箱拒绝创建进程、读取目标或执行临时文件，与 Windows 管理员权限、反作弊保护不是同一故障。记录原始错误和失败阶段，按环境允许方式请求权限；不要通过关闭保护或反复重装编译器猜测修复。

DevTools capture 结束会断开适配器，但原生 DLL 可能仍被游戏加载。只在目标正常退出后清理报告指出的那个 scratch 目录，不递归删除任意系统临时目录或其他任务文件。
