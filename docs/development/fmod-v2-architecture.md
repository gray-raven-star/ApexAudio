# FMOD JSON V2 本地架构

状态：架构草案。本文记录已确定的产品约定和拟议逻辑接口设计，不表示这些接口已全部实现。现有实现及验证证据由[试验说明](v2-trial.md)和[试验基线](owner-v2-baseline.md)分别描述；领域用语见[项目术语](../../CONTEXT.md)。

接口 ID 和 FM-REQ 编号是稳定的架构契约引用，不是执行任务或实现进度。逻辑接口不要求各自建立项目、类或 IPC 方法。

## 范围与已确定产品约定

玩家能够离线导入 FMOD JSON 配置包及已知来源的共享后端，保留同一包的多个版本，明确选择当前版本，匹配运行游戏，建立固定会话并使用原有采集、录音、试听和震动功能。失败应指出原因与可执行的下一步；包更新、回退和卸载保留用户数据。已有 V1 包及 Owner 0.2.0 配套包/后端继续可用。

范围限于现有 FMOD 采集能力、JSON 配置、EXE 与目标进程实际加载模块的证据。Lua、Wwise/Unreal 共享化、在线目录、自动下载、认证评分、面向用户的适配测试系统、任意脚本或设置转换框架均后置。FMOD/Wwise/Unreal Audio 是第三方音频系统，本仓库的采集实现连接这些系统；运行时能力不由产品名“V2”推断。

## 模块职责与数据归属

| 逻辑模块 | 负责与拥有的数据 | 依赖边界 |
|---|---|---|
| 桌面与应用协调 | 用户选择、操作结果、会话生命周期与资源释放责任 | 调用包/后端仓库、匹配和会话接口；不解释 FMOD 内部布局 |
| 包仓库 | 不可变包版本、当前版本指针、安装完整性与依赖状态 | 当前选择按包 ID 独立持久化；不连接游戏或管理用户录音 |
| 后端仓库 | 固定后端版本、描述、内容摘要和支持范围 | 提供已校验本地文件；不猜测游戏兼容性、不自动跟随最新版本 |
| 证据与匹配 | 实际目标证据、逐条构建记录匹配、候选与原因 | 只读实际 EXE 和已加载模块；不加载采集 DLL |
| 会话准备 | 包/Profile/参数/后端/目标/完整候选集合的固定快照与使用记录 | 输入来自前述模块；在连接期间保持不变 |
| 引擎采集后端 | 引擎参数解释、必需证据规则、重验、采集控制和音频输出 | 通过既有 IPC 提供能力；原生模块在游戏内执行采集，独立进程不是安全沙箱 |
| 用户数据仓库 | 用户预设、显示组织、历史录音及其录制时元数据 | 独立于包安装和卸载，不能由新包重新解释原录音 |
| 作者工具 | JSON 模板、静态诊断、完整性生成和打包 | 复用格式与支持范围契约，不运行包代码、不连接游戏 |

数据依赖为：包当前选择和实际目标 → 完整记录匹配 → 固定会话及后端依赖 → 后端身份核对、只读重验 → 连接 → 冻结分组与音频/反馈数据。录音和反馈各自消费已定义的数据路径；包更新只影响未来连接。

## 共用数据与错误契约

### FM-REQ-01：版本身份、选择和状态

- `PackageVersionRef`：包 ID、确切版本、清单 SHA-256。清单及其登记文件必须校验一致；相同 ID/版本出现不同内容时拒绝覆盖，相同内容可幂等导入。
- `BackendRef`：后端 ID、确切版本、描述摘要和变体；平台及支持范围由后端发布描述声明。Profile 固定依赖，不设全局后端版本，也不自动选“最新”。
- `TargetIdentity`：PID、UTC 启动时间 ticks、实际 EXE 路径。`TargetEvidence` 附该目标的 EXE 摘要，以及实际加载模块的名称、路径、摘要或逐项不可取得原因。
- `BuildMatch`：匹配结果、完整候选记录与引用的 Profile、使用的证据。成功合并同 Profile 候选时保留候选集，不伪造唯一构建。
- `PreparedSession`：会话 ID、包版本身份、清单摘要、Profile、固定后端、目标身份、匹配候选及证据、参数快照和相应格式版本。它是一次连接的不可变输入。
- 包版本具有“已安装”和“是否当前”两个独立属性，依赖就绪状态可重新计算；“会话正在使用”由运行会话单独表达。每个包 ID 至多一个当前默认版本，不同包 ID 互不排斥。
- 会话逻辑状态为未准备、已准备、后端就绪、已连接、正在采集、已结束；故障另记录主错误和清理结果。存在未完成清理或须重启游戏的残留时，不宣称已完全恢复。

**不变量**：目录布局不构成公开身份；选当前版本只影响下次连接；会话使用的包、参数和后端不能被更新覆盖或删除。首次导入也不隐式选择当前版本。包 schema、IPC、启动上下文、引擎参数各自演进，不统一改号。

**可观察行为**：调用方可明确指出“已安装的哪个版本”“下次默认哪个版本”“当前会话固定哪个版本”；重新启动主程序可恢复当前选择，不能把安装成功当作当前选择或连接成功。

### FM-REQ-02：结果和失败语义

所有逻辑接口返回成功值或结构化错误：稳定 `code`、用户可读 `message`、定位用 `details`、可执行 `nextAction`。`details` 能表达失败阶段、包/版本/Profile、字段或文件、预期与实际、清理结果，但每次只提供与该错误相关且实际取得的内容；没有预期值、实际值或关联实体时不伪造字段值。仅在诊断需要时提供路径，不默认对外上传本机信息。

| 稳定错误类别 | 含义 | 下一步示例 |
|---|---|---|
| `package_invalid` / `version_content_conflict` | 结构、摘要、引用错误，或同版本内容冲突 | 重新取得包、使用新版本号 |
| `backend_missing` / `backend_unsupported` | 固定后端缺失或不支持参数组合 | 手动导入对应后端、选其他包版本 |
| `evidence_insufficient` | 目标/模块信息不可读、必要模块尚未加载，不能判断匹配 | 检查权限、等待初始化、重试 |
| `build_mismatch` / `profile_conflict` | 证据可读但无完整匹配，或不同 Profile 同时匹配 | 选择正确包/版本、明确选择候选配置或修正包 |
| `target_changed` | 目标退出、重启或路径/启动身份变化 | 重新准备连接 |
| `version_in_use` / `current_version_selected` | 删除对象正在使用或仍为当前版本 | 先断开，或先改选/清除当前 |
| `backend_start_failed` / `protocol_mismatch` | 程序启动、握手或版本不兼容 | 补齐运行环境、取得正确后端 |
| `capture_not_ready` / `capture_failed` | 音频尚未初始化或采集操作失败 | 等待重试，或查看具体原因 |
| `group_invalid` | 请求包含未知或不可采集的分组 | 刷新实际组列表后重新选择 |
| `operation_cancelled` | 操作在提交前被取消 | 保持原选择，按需重新发起 |
| `restart_required` / `cleanup_incomplete` | 已加载不同 DLL 或清理未完成 | 重启游戏；清理完成前不继续连接 |

这些是逻辑错误类别，不要求立刻新增同名异常类或修改全部旧协议。旧 V1 错误保留可读消息，可映射为较宽类别，不能凭消息猜出没有的证据。

长操作支持取消：安装或当前选择原子提交前取消时，不留下半安装成功记录或新的当前选择；若已原子提交，则明确返回已提交的身份与结果，不能仅报“已取消”让调用方误以为操作没有发生。会话操作取消后由协调器释放其资源与使用记录，报告无法完成的清理，不要求 UI 或调用方猜测资源归属。

**可观察行为**：界面和协调逻辑按稳定代码给出重试、补依赖、重选或重启操作；失败不依赖中文字符串分支，不把有残留资源的失败显示为完全回滚。

## G1：配置包安装与当前版本

提供方为包仓库逻辑，调用方为桌面操作、会话协调和作者工具。以下接口使用 FM-REQ-01/02，共同依赖固定包身份与原子持久化；资源校验不执行包内程序。

| 契约 / 逻辑接口 | 输入 → 成功输出、状态变化 | 失败语义与不变量 | 可观察行为 |
|---|---|---|---|
| FM-REQ-03 `Package.inspect` | 归档路径 → 包身份、格式、来源声明、执行形态及检查结果；不安装、不改当前 | 读取不了或结构不合法返回文件/字段；检查结果不是兼容认证 | 用户能在导入前看到包的种类与来源；失败不留下安装记录 |
| FM-REQ-04 `Package.import` | 归档 → 校验后的 `PackageVersionRef`、缺失依赖；新增已安装版本 | 缺后端可安装但不可设当前；同版本冲突拒绝；失败保留所有旧版本和当前选择 | 导入新版或重复导入后，旧版仍存在，当前版本不变；首次导入后仍需明确选择 |
| FM-REQ-05 `Package.listVersions` | 包 ID 或全部 → 安装版本、当前标记、依赖状态、使用中的会话 | 只读；损坏版本应标明具体错误，不令其他包消失 | 界面能同时列出同包多个版本和它们的不同状态 |
| FM-REQ-06 `Package.selectCurrent` | 包 ID、已安装版本身份或显式清除 → 持久化当前选择 | 这是元数据选择，不调用会断开当前会话的选包操作；指定版本完整性和其声明的全部后端依赖须就绪，失败保持原选择。首期不做部分 Profile 激活 | 每包 ID 一个当前版本；重启后恢复；进行中会话不变，下一次连接采用新选择 |
| FM-REQ-07 `Package.removeVersion` | 精确包版本身份 → 删除该安装版本 | 正在使用时拒绝；仍为当前时要求先改选或显式清除；不自动删预设、录音或共享后端 | 可移除闲置历史版本；删除不会影响其他版本、其他包和用户数据 |

**依赖**：FM-REQ-06 依赖 G2 解析依赖，FM-REQ-07 依赖 G4/G5 的会话使用记录。旧 V1/0.2.0 单版本安装布局升级到新存储索引时，必须继续发现原安装记录并保留用户数据，不要求用户重新制作或重新打包；不擅自运行包。现存选择可以保留，不能借新导入改变它。

## G2：共享后端安装、解析与支持范围

提供方为后端仓库及具体引擎后端，调用方为导入操作、包选择和会话准备。首期只显式手动导入已知来源后端；展示来源与内容校验结果，不建设下载服务或认证目录。

| 契约 / 逻辑接口 | 输入 → 成功输出、状态变化 | 失败语义与不变量 | 可观察行为 |
|---|---|---|---|
| FM-REQ-08 `Backend.import` | `.gbackend` → 身份、内容校验结果、本地安装记录 | 同 ID/版本不同内容拒绝；不覆盖会话使用文件，不改包当前选择；摘要不是来源证明 | 两个包固定同一后端时复用同一安装，不同版本并存 |
| FM-REQ-09 `Backend.resolve` | 固定依赖 → 已校验文件与确切描述，或缺失项 | 不选其他版本凑合，不启动程序、不连接游戏 | 缺失时能准确给出需要手动导入的 ID/版本/变体 |
| FM-REQ-10 `Backend.describe` | 后端身份及参数格式/变体 → 支持范围、协议/上下文版本、定位方式、数量和参数组合限制 | 声明与运行时校验一致；不支持须明确拒绝，不由配置包自行放宽 | 作者工具和连接准备能解释为何某 Profile 不受支持 |

**依赖**：FM-REQ-01/02；G4 使用解析结果，G7 使用支持范围做静态检查。

## G3：实际目标证据与完整记录匹配

提供方为只读目标证据收集和构建匹配逻辑，调用方为会话协调；不在 UI 中识别引擎 ABI，不注入 DLL。

### FM-REQ-11 `Target.collectEvidence`

- 输入：选中 PID 与待核验的 EXE/模块声明；输出：目标身份、EXE 摘要、实际加载模块的名称/实际路径/摘要和不可取得项。
- 成功：取得所需证据，不改变游戏或包；模块名需唯一定位到实际加载模块，重名或不可读时返回具体原因，不猜路径。
- 失败：目标退出/重启为 `target_changed`；模块尚未加载、权限不足或文件不可读为 `evidence_insufficient`。不能把未取得证据写成哈希不匹配。
- 不变量：只对 EXE 与已加载模块收集证据，不引入磁盘全盘扫描、任意游戏安装根发现或版本号猜测；会话准备和实际连接仍复核目标变化。
- 可观察行为：调用方能区分已读且不符、尚未加载、无法读取和目标已改变，并指出对应文件/模块。

### FM-REQ-12 `Build.match`

- 输入：选定包版本的构建记录、同一目标的实际证据；输出：`Matched`、`Mismatch`、`EvidenceInsufficient` 或 `ProfileConflict`，附逐条完整记录的比较依据。
- 成功：一条记录要求的 EXE 和全部已声明关键模块均精确匹配。多条完整记录命中且引用同一 Profile 时合并为一个 Profile 选择，并将所有命中记录作为准备候选集合保留；会话不能声称唯一构建已确认。命中不同 Profile 时由用户明确选择候选，或要求修正配置；不默认挑第一条。
- 失败：任一可取得关键证据不符，该条记录不能通过；尚有必要证据不可取得时报告证据不足。多条记录之间不能拼接命中项，不定义 SHA-256 相似度，也不对未知构建警告放行。
- 状态：只读；结果因目标身份、文件证据或包版本变化而失效。没有可解释的匹配结果时不能进入 G4。
- 可观察行为：同 EXE、不同模块组合可按各自完整记录区分；不同 EXE 构建可共用 Profile；相同 Profile 多候选保留证据，不误报为不同 Profile 冲突。

**依赖**：G1 提供明确版本的记录，FM-REQ-01/02 提供证据和结果契约；G2/引擎规则明确哪些关键模块必需，包不能漏填绕过。G4 固定匹配结果，G5 在加载前重新核验。

## G4：准备并固定一次会话

### FM-REQ-13 `Session.prepare`

调用方为工作台连接操作，提供方为应用层会话协调。输入为明确包版本（默认取该包当前选择）、目标身份和经用户消歧后的匹配结果；输出为 `PreparedSession`，状态由未准备变为已准备。

成功时固定包/清单内容、Profile 参数、匹配候选与证据、确切后端和目标身份；建立对应版本的使用记录。同 Profile 多候选固定原准备候选集合，不强造唯一 Build；后续复核结果另行返回，不能改写原集合。准备期间若当前选择改变，不重新读取成另一版本。返回结果不等于游戏已连接。

依赖缺失、参数不支持、匹配冲突未解决、目标或文件证据改变时返回具体错误，不启动采集、不改变当前选择。准备中断释放已取得的本地资源和使用记录；不能把游戏内已发生操作称为准备阶段可完全回滚。

**不变量**：Core 不解释 FMOD 对象布局；后端解释引擎参数。启动上下文采用与目标后端兼容的独立版本，旧 V1 不接收新命令，Owner 0.2.0 使用其原上下文。数据根和资源定位由仓库接口提供，连接协调不推断存储目录布局。

**可观察行为**：准备结果足以准确复述本次连接将使用哪个包、Profile、后端和目标；准备后安装新版本或改变当前选择不影响该结果；使用中的版本不能被删除。

## G5：连接、采集与释放接口

下表沿用已有 IPC 方法名，约定各操作的架构语义。调用方为通信客户端/会话协调，提供方为独立后端；详细状态和失败设计不要求新建另一套协议。所有有副作用的方法使用 G4 固定会话，遵守 FM-REQ-02；V1 仅调用原先支持的方法。

| 契约 / 沿用方法 | 输入 → 成功输出 | 状态与失败语义 / 不变量 | 可观察行为 |
|---|---|---|---|
| FM-REQ-14 `GetInfo`、`GetCapabilities`、`GetBackendInfo` | 无 → 协议/能力、实际后端身份/上下文摘要 | 启动后首先核验；V1 不强求 `GetBackendInfo`；不匹配结束后端并报告，不能继续连接 | 实际进程身份、依赖及上下文一致才进入后端就绪 |
| FM-REQ-15 `ValidateTarget` | 与会话一致的目标及原准备候选集合 → 允许与否、仍完整命中的记录集合及逐项原因 | 只读逐条复核，不加载采集 DLL，不自动选另一 Profile；至少一条原候选完整匹配且满足后端必需证据才允许；证据不足/不符/目标变化分别报告 | 条件不满足时连接停在注入前；保留原集合并返回本次仍命中的集合，不强造唯一构建 |
| FM-REQ-16 `Connect` | 已准备目标及原候选集合 → 连接状态、仍完整命中的记录集合及结果 | 就绪→已连接；加载前再次逐条独立复核，至少一条原候选完整匹配且满足后端必需证据才加载；失败清理并报告残留；DLL版本冲突要求重启，不擅自卸载 | 只有实际完成连接才显示已连接；不拼接候选证据、不切换未准备的 Profile；离线上下文不能转为真实连接 |
| FM-REQ-17 `GetAudioGroups` | 无 → 实际可用组 ID、名称、层级、PCM/包含子组能力 | 连接后确认最终列表；会话内列表及顺序固定，稳定 ID 不用数组索引替代；列表非法不开始采集 | 同一会话内包索引始终对应同一组，主程序可按稳定 ID应用设置 |
| FM-REQ-18 `StartCapture` | 稳定组 ID 列表 → 已应用请求及实际传输状态 | 先完整验证请求，再改变采集状态；未知或不可采集组拒绝并保留原PCM请求范围。空列表返回 Connected=true、Capturing=false 和空独立组范围，不隐式全选；内部worker是否存在不改变外部状态含义；录音默认全选由主程序明确发出 | 合法请求替换原PCM范围；无效请求不干扰原采集；合法替换期间的系统失败报告最终实际状态及清理结果 |
| FM-REQ-19 `SetFeedbackGroups`、`GetFeedbackSource` | 反馈组 ID / 无 → 应用状态 / 格式、映射名、产生进程 | 仅在后端支持实时混音并连接后使用；空组使反馈混音静音；不改游戏音量，不停止独立采集 | 取消全部反馈后震动源静音，独立录音继续 |
| FM-REQ-20 `StopCapture` | 无 → 停止后的实际状态 | 停止独立传输、保留控制连接和连接存活租约；幂等；实时反馈按已有选择继续，Disconnect 才终止连接和反馈 | 停止后控制请求仍响应、反馈可继续；等待后可重新开始独立采集 |
| FM-REQ-21 `Disconnect`、`Shutdown` | 无 → 已释放/残留结果 | wire Disconnect 停止原生采集与反馈、释放目标句柄和映射，但保留控制管道及后端进程；Shutdown 结束后端。未连接时幂等。失败保存主错误及清理失败，已加载DLL不等于可以卸载 | 应用层关闭会话时停止录音并保存数据，再编排 Disconnect→Shutdown/回收进程→关闭IPC；使用记录持有到实际占用文件的后端退出或残留已明确处理，不能完成时说明重启要求 |

### FM-REQ-22：音频与反馈数据契约

后端提供已有独立 PCM 管道及可选反馈共享内存，主程序录音/试听与反馈提供器分别消费。独立数据为 48 kHz、双声道 PCM16；分组索引指向本会话冻结列表，时间戳、序列号用于对齐和发现丢失。反馈源沿用其独立格式，不能当作 PCM 管道互换。

成功是收到符合协议的实际数据并维持原有录音、试听和反馈功能；格式错误、后端退出、目标失效或数据路径失败时结束相关会话并保存已录内容，不显示适配认证。协议数据正确也不能证明声音语义或长期稳定性，需工程实机验收。

### FM-REQ-29 `GetStatus`

调用方为工作台及连接协调，提供方为后端。无额外输入，返回本会话的实际连接、独立采集、反馈可用状态及具体原因；查询不改变状态。目标退出、原生采集失效、worker 停止时应更新对应状态，文字说明与标志保持一致。接口读取失败按通信故障处理，不能沿用过去的“正在采集”当作成功。

可观察行为是停止独立采集后仍能区分“连接保留、独立传输已停”和“目标或后端失效”；正常停止不被工作台误判为断线，真正失效触发有原因的会话结束。

连接存活租约归连接生命周期拥有，独立于 PCM worker；停止独立传输不能停止连接心跳或使反馈随租约超时失效。请求参数验证先于状态改变，合法替换中的系统失败才进入故障清理。原生 ABI 支持范围归后端，普通配置不能任意指定调用签名。

**依赖**：G4、FM-REQ-02、G6/G8 的数据保存与状态更新。切换包版本不触发当前会话热重载；若以后定义动态分组，应另立不兼容契约，不在本阶段加入。

## G6：有限设置保留与历史录音

提供方为现有预设/录音逻辑和应用层选择，调用方为版本切换、连接及用户编辑。

### FM-REQ-23 `Preset.resolveForGroups` / `Preset.applyMapping`

输入为包 ID、所用版本、实际组列表、原预设及可选明确一对一映射；输出为可用设置、保留的旧设置和需用户重配项。仅在用户保存时原子持久化相应副本，失败不覆盖原稿。

范围以实际字段为准：组的 `Name/Enabled/FolderId/Order`、显示文件夹的 `Id/Name/ParentId/Order`，以及预设名称、身份和作者基础引用。语义不变且能明确对应时保留；新组默认 `Enabled=false`；删除或暂不可用组不参与当前采集/反馈或文件夹批量操作，但保留旧条目用于回退。当前操作只针对实际可用组，不因旧条目仍在预设中就调用不存在组的接口。拆分、合并、ID 或语义改变且无法可靠对应时提示部分重新配置；不猜测映射、不建设任意转换框架。

可观察行为是用户能识别哪些设置保留、哪些需重配；回退后保留项可恢复。包升级不能重置全局增益、端口、主题、录音偏好、热键、手柄绑定或自动行为。`LastPackId/LastPresets` 只更新对应选择引用，不充当版本身份。

### FM-REQ-24 `Recording.load` / 包操作的数据保留

输入为历史录音 ID；输出为录制时保存的包版本、轨道 ID/名称和音频。读取不依赖当前安装包或新 Profile 重新解释。包导入、改选、回退和删除只操作其归属文件，不顺带删除预设或录音。

成功是卸载或更新包后仍能列出、播放原录音；无法读取时指出录音自身的文件或格式问题，不将“新包没有此组”视为录音失效。原始声音字节不因包更新重写。

## G7：作者工具静态制作流程

提供方为 `PackV2` 和共用校验逻辑，调用方为适配作者。以下逻辑操作可以由同一CLI入口承载；不新增在线服务、不执行配置内代码、不连接游戏。

| 契约 / 逻辑接口 | 输入 → 输出与状态 | 失败语义与不变量 | 可观察行为 |
|---|---|---|---|
| FM-REQ-25 `Author.create` | 新定义目录及包/后端选择 → 最小 JSON 模板与说明 | 不覆盖已有内容；占位项明确标记，不能默认为已知构建 | 作者获得与选定后端参数格式一致的起点 |
| FM-REQ-26 `Author.validate` | 定义目录及本地后端描述 → 逐文件/字段的静态结果 | 检查路径/链接边界、大小数量、重复路径、摘要、引用、版本/参数组合、稳定ID与层级；占位和必需证据缺失明确报错 | 作者能据文件和字段修复；通过只表示静态条件满足 |
| FM-REQ-27 `Author.package` | 校验通过的目录与输出路径 → `.gpack` 身份/摘要 | 输出不得覆盖定义输入；生成登记文件摘要并再次校验；失败不留下可误用的正式产物，不启动后端 | 包导入后保留多构建各自证据和共享Profile引用，不需作者编译采集器 |

## G8：桌面交互与正常运行状态

### FM-REQ-28：从安装到连接的界面契约

调用方为用户，提供方为现有 Desktop/Application。输入是导入、明确选择当前版本、选目标、连接、断开及版本移除操作；输出是对应包版本列表、依赖状态、当前默认与本次使用版本，以及操作的实际结果。

导入后显示“已安装/缺少依赖”等事实，并提供明确选择当前版本的操作；首次导入不偷偷设当前。不同包 ID 各自保留当前选择，进行中会话另显示固定版本；改选只对下次连接生效，不强迫断开或自动切换 DLL。当前主程序同时一会话的能力保持不变，不把每包可有当前版本误解成多游戏并发采集需求。

界面区分 V1 包内程序与 JSON 共享后端配置，显示作者和声明来源；来源声明不能冒充认证。Lua 尚未接入，不显示已支持脚本。连接检查错误使用 FM-REQ-02 的明确下一步，例如补后端、等待初始化、重新选目标或重启游戏。成功只显示“已连接”“正在采集”等实际状态，不新增兼容评分、认证或适配测试面板。

可观察行为是玩家能通过界面完成本文本地闭环，区分当前默认版本与会话版本，并在失败后完成明确的恢复动作。选择当前版本是元数据操作，不触发当前会话的断开或重连。本接口依赖 G1～G6 的结果和状态契约。

## 依赖关系与设计取舍

- 版本身份和错误契约是各逻辑模块的共同边界；包仓库依赖后端解析判断可选状态，后端仓库不反向修改包的当前选择。
- 完整记录匹配依赖只读实际证据和后端必需证据规则。会话准备依赖包版本、后端依赖和匹配结果；采集后端再次验证，不能把主程序结果当作免检授权。
- 用户设置由稳定组 ID 对应，实际操作只使用本会话可用组；复杂语义变化交由用户重新配置，保留旧数据供回退。此取舍优先保持可解释行为，避免通用迁移框架。
- 已安装、当前默认、会话正在使用分别建模，使导入和改选不破坏正在连接的文件。相对于连接期间禁止改选，采用“改选只影响下一次”保留用户操作自由，同时要求使用记录阻止删除在用版本。
- 同 Profile 多构建候选保留完整记录集合，连接前逐条重验；相对于强制构建唯一，此设计允许多份同义已知记录，但不允许跨记录拼接或在未准备的 Profile 间切换。
- V1 原流程、Owner 0.2.0 配套流程和新上下文分别按自身契约运行，避免产品名称驱动所有协议一起升级。参数支持边界及原生模块能力归后端所有，超出范围仍可用专用适配器。

## 用户可观察的契约场景

- 首次导入后明确选择当前版本；导入缺依赖新版时原选择及旧版仍可使用。
- 同包多个版本、不同包各自的当前默认、多个后端版本可并存；主程序同一时刻只维持一个活动游戏采集会话。
- 实际模块未初始化、不可读、不匹配与不同 Profile 冲突有不同原因；通过普通检查后继续正常连接，不展示认证结论。
- 连接期间改选版本不改变本次参数、后端和分组顺序；删除在用版本被拒绝，DLL 版本冲突要求重启。
- 空反馈组静音而独立录音继续；空独立采集组不输出 PCM，返回 Connected=true、Capturing=false 和空独立组范围；停止独立传输后连接租约和反馈保持，之后可恢复传输。
- wire Disconnect 释放游戏连接资源后仍可通过控制管道请求 Shutdown；应用层关闭会话保存录音，回收后端后再关闭 IPC，并在实际占用释放或残留明确处理后解除版本使用记录。
- 更新、回退和卸载保留录音；旧设置能明确对应时保留，不能可靠对应时说明需要重新配置哪些部分。

这些场景用于说明接口的外部行为，不定义测试计数、认证状态或实施进度。
