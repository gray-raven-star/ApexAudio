# 开发新的采集模块

## 最小职责

主程序不应知道目标游戏或引擎。新模块负责核对目标版本、找到音频实例、枚举稳定分组、挂接音频回调、输出独立 PCM、接受选择并正常停止。

新模块通常分成两层：独立适配器进程实现公共协议；可选的原生 DLL 在游戏音频渲染位置复制数据。允许用别的语言或进程间接口，只要完整包自带私有依赖并遵循宿主协议。独立进程隔离崩溃，但不是安全沙箱。

## 创建骨架

```powershell
pwsh -File tools/New-Pack.ps1 -Id author.example -Name "目标游戏" -Backend Custom -Directory gamepacks/example
```

`adapter/Program.cs` 是 IGameAdapter 的空实现，Connect / StartCapture 会明确拒绝未实现操作。修改 Info 的真实身份与能力，实际实现以下操作：

| 操作 | 实现要求 |
|---|---|
| Connect | 核对 EXE / 调用模块摘要，定位并验证对象和接口，再初始化采集资源 |
| GetAudioGroups | 返回稳定 ID、有序且不循环的父子树、名称来源和实际 HasPcm |
| StartCapture | 从有界缓冲读取真实独立声音，转换为公共格式，并调用 output |
| GetStatus | 保持响应，报告实际连接、采集与丢块状态；不要永远硬写 true |
| StopCapture | 取消后台任务并等待结束，不释放任务仍在使用的内存 |
| Disconnect / Dispose | 停用采集、按接口移除监听／DSP、释放自己拥有的资源 |

`src/ApexAudio.Contracts/Transport.cs` 的 AdapterServer 负责管道服务；`Models.cs` 定义消息。非 C# 实现按 adapter-protocol.md 编码字节帧，不需要引用这些 DLL。

## 如何取得声音

优先选择引擎正式回调或 pass-through DSP，复制原缓冲并让游戏继续使用原数据。不要修改原音频、音量或状态，不要覆盖游戏正在使用的效果槽。

静态链接、隐藏导出或不同版本可能需要包内定位器。把定位结果与程序摘要绑定；若结构未知，先做只读核对。C++ 接口可用对应 SDK 编译，或在明确 ABI 后用 C 表达函数表；GNU C++ ABI 不能直接替代 Windows MSVC C++ 接口。

必须确认：指针有效性与所属模块、函数参数及返回值、虚函数调用槽、结构对齐、通道顺序、回调阶段、对象所有权和线程要求。注册请求被加入队列不等于已经执行；以实际回调和有效 PCM 验证。

在原生模块里设计自己的 Configure / Start / Stop / Select 接口或同等机制，返回明确错误码。不要在宿主中增加私有命令处理某个游戏。

## 回调和传输

音频回调只做有界的复制、转换和发布：

1. 验证输入帧数、通道和采样率。
2. 按真实布局下混立体声；如需重采样，在包内实现，不伪报 48 kHz。
3. 为每组保存本轮有效数据，避免清理时序丢掉整轮音频。
4. 将 PCM 和第一帧 QPC 时间戳写入有界环形缓冲。
5. 在回调外的工作任务中写管道；报告覆盖和丢块。

公共数据为 48 kHz、双声道、交错 PCM16，每包最多 2048 帧。groupIndex 引用同一次连接固定顺序的分组数组。时间戳使用系统 QPC，不用 Unix 时间或进程相对起点。

静音允许不发包，状态和保活仍应继续。后台、暂停和等待资源都可能造成无声音，不能简单用“几秒没声音”判定连接失败。停止时保证没有回调再使用已释放的资源；异步移除必须完成后再释放监听对象。某些模块在进程结束前不能卸载，需在包 README 说明更新时重开游戏。

## 低延迟反馈

实现 IRealtimeMixAdapter 或同等协议方法：GetFeedbackSource 返回公共映射格式与生产者 PID；SetFeedbackGroups 原子应用选择，空选择输出静音。

只混合被选择且未被聚合父组覆盖的组；不要重复叠加父子内容。录制范围独立于反馈选择，切换选择不重启录音、游戏或 X-Haptics。

共享缓冲区格式在 adapter-protocol.md。回调、实时混音和保活不依赖录音管道完成发送。积压时丢弃过时反馈而非排队回放；录音原始时间戳保持不变。这个接口提供声音输入，不代表马达物理测量。

## 如何自测

开发自测可用合成缓冲检查字节布局、下混、时间戳、空选择、父子去重和停止；Mock 是完整公共协议示例。涉及虚函数时必须从实际使用的函数表槽调用，不能直接调用处理函数绕过 ABI；涉及渲染阶段时，按目标实际的调用顺序测试。

模拟检查仍不能证明真实对象、注册签名或游戏音轨正确。实际测试与报告见 validation.md。未经验证就发布时必须明确标记能力和限制。

## 构建和维护

完善模板后执行 Build-GamePack，或自行发布完整运行目录，再执行 Pack.ps1。实现源码留在开发项目；`.gpack` 只装运行所需文件、配置、预设、README 和许可。

游戏版本差异配置化，接口结构差异放在版本明确的包内后端；只有公共协议确实不足时才提出通用协议扩展。更新模块使用内容摘要文件名或明确版本，避免加载同名旧 DLL；不要通过重复注册相同工厂、复用旧实例掩盖未重启的问题。
