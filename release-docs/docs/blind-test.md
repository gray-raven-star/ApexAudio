# 其他 AI 的独立适配评审

## 输入

给接收者完整开发套件、目标游戏的本机位置、操作授权范围及用户可协助开机／开游戏的条件。让其先读 START-HERE.md 和 AI-INSTRUCTIONS.md。

不提供目标游戏旧包、旧定位结果、分组、调查脚本、历史聊天答案。套件包含引擎后端源码、协议示例和通用工具；这是工具输入，不是目标游戏答案。

## 独立性

在新目录解压；不访问原开发者工作目录、缓存或历史适配。每个 AI 自己记录首次遇到的问题和采取的步骤。可以按说明安装正常开发依赖、检索公开资料和调查被授权的目标；使用来源需记录。

## 交付

- 可导入的真实 `.gpack` 或明确的失败阶段；
- 新增配置／模块源码及构建命令；
- 依据、依赖、已验证与未验证内容；
- 使用用户操作的次数和目的；
- 文档或工具缺口，不能仅写“没有接口”。

程序判断只读调查不可确认时，仍应说明接下来如何核对。接口确实缺失或布局不匹配时，在包内扩展或提出具体缺口，不要求主程序增加该游戏分支。

## 如何比较

比较复现性、修改范围、真实音轨、切换稳定性和失败证据，不只比较是否生成压缩包。停止条件是明确的技术阻塞或完成验证，不能把尚未尝试的步骤写成不可能。

原维护者不代替接收者完成盲测。反馈用于修补通用文档和工具；不以直接提供目标游戏答案来让分数变好。
