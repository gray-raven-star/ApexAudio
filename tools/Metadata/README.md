# 有限的资源与名称辅助工具

这些是只读源文件的开发辅助，不是通用解包器，也不连接游戏。用 Python 3，先执行各脚本 `--help` 核对当前参数。压缩依赖在 requirements.txt，只有用到相应功能才需要安装；不属于主程序依赖。

| 脚本 | 输入与边界 |
|---|---|
| read_re_pak.py | 已实现的 RE PAK 4.0 布局，按 `--resource` 指定的完整资源路径提取；不负责猜资源路径。部分索引处理需 `--cipher-reference` 指向经核对的公开格式参考；资源级加密不支持 |
| read_ue_pak.py | 标准 v11 完整目录索引，按 `--target` 后缀限定小型资源；不支持 IoStore、加密索引或任意压缩。可选 `--ooz` 需要可信的 OozDecompress 封装库和 `--decoder-sha256` |
| merge_layers.py | 多个读取报告按重复的 `--report` 参数顺序合并，最后一层优先；实际覆盖顺序由开发者调查，不由文件名字母排序推断 |
| name_candidates.py | `--definition`、每行一个名字的 `--candidates` 和 `--output`；对现有 Wwise ID 做有限 FNV-1 名称候选匹配，不确认原始大小写或声音语义 |

读取器会限制索引、资源大小和输出数量，并拒绝未实现格式。失败时检查报告的具体阶段，确认目标版本与源码支持范围；不要删掉限制后解出整个游戏作为默认解决办法。现有范围不覆盖时，可以使用合适的公开读取器或实现包内开发工具，保存依据和版本。

原始资源、完整名称库和全量转储不应混入 .gpack 或通用开发包。使用过程见 [调查方法](../../docs/investigation.md)，名称与预设见 [分组依据](../../docs/group-evidence.md)。
