# 怪物猎人：崛起 · ApexAudio 适配包 0.1.1

## 导入使用

1. 打开 ApexAudio 0.1.0，在游戏适配包页面导入 `MHRise-ApexAudio-0.1.1.gpack`。
2. 按程序提示确认本包来源，游戏启动并有声音后连接。
3. 初始反馈开关全部关闭。先录一小段，再逐组试听、重命名并选择需要的反馈组。
4. 父组包含子组声音；同时选父子组会叠加。独立录音不受反馈开关影响。

本包绑定本机 Steam build **17920865** 的 `MonsterHunterRise.exe`。
SHA256：`29FA23A9CE24613A9B05CE84F7EBFA3262AAF5053B377B43FD8DFC09071AA7FC`。
游戏更新、其他平台或 EXE 内容改变后会拒绝连接，不会跳过摘要校验。

## 实际提供的内容

- 从当前游戏补丁中的 Init.bnk 解析 143 条普通总线，保持真实父子层级。
- 其中 142 条配置为可采集；主混音已有 4 个效果槽全部占用，**只展示层级，不插入采集器**。
- 67 条辅助混响总线保存在定义中，不当成普通独立采集组提供。
- 143 条普通总线中，72 条有参考名称，包括玩家武器/挥动/命中/脚步、怪物音效/语音、随从猫狗、NPC、界面、对白和多类音乐。其余 71 条保留编号，能按父组归类的标为“某类 · 未命名组”。
- 参考名通过当前游戏设置字符串、有限资源词汇组合与 Wwise FNV 对应，并结合实际总线层级核对。只有少量直接来自设置字符串；多数是哈希恢复候选，不是从原始总线名称表提取，也没有逐组试听确认。英文大小写不保证与原作一致。详情见 evidence/name-restoration.json。
- 标题画面已实测发声的总线：`253003338`、`3145001837`、`3179867851`。第一条是后两条的上级，存在预期的父子内容重叠。
- 采集使用主程序导出的 Wwise 接口，在静态银行确认空闲的效果槽插入透传采集器，只复制音频。
- 效果槽的静态空闲不保证以后不会被游戏或其他模组动态占用；本包没有声称已验证所有场景。

## 验证范围

构建、完整性、适配器协议与原生透传自测通过。用户启动游戏后进行一次 6 秒基础采集，收到 843 个音频包、3 条非零总线，摘要不同，未报告丢块或传输错误。142 条配置总线的挂接调用均返回成功；这不等于每条都已发声或语义已确认。

没有继续要求用户进行分组测试。完整游戏内语义、所有场景、重连和游戏退出场景、物理手柄反馈留待用户测试。报告见 `validation-report.json`。

连接会把本包模块和临时采集效果银行加载到游戏进程；正常断开移除采集效果与回调，模块驻留至游戏退出。测试已正常结束，游戏保持运行。没有修改游戏文件、玩法、数值或存档；不包含模拟音轨，不绕过反作弊，不安装 REFramework 或玩法模组。

## 构建与来源

配套源码包包含实际使用的 Wwise 后端及公共依赖源码、游戏定义、预设、元数据读取工具和验证记录，没有改动 ApexAudio 主程序。

源码根目录执行：

```powershell
pwsh -File tools/Build-GamePack.ps1 -DefinitionDirectory gamepacks/mhrise -Compiler '完整DevKit路径/toolchain/zig/zig.exe'
```

需要 Windows x64、PowerShell 7、.NET 8 SDK、DevKit 随附的 Zig 0.15.2。输出 `dist/packages/independent.mhrise.wwise.gpack`。
运行本包不需要 Python、Zstandard、wwiser 或额外解包器；它们仅用于离线调查。来源说明见 `DEPENDENCIES.md`。
