# 行商浪人适配包：分组名称核对

结论：当前 Init.bnk 没有直接提供完整可读总线名表，但“任何工具都无法得到 Music / Dialogue 等名字，只能按场景试听”过于绝对。部分名称仍可通过有限候选哈希与当前总线编号交叉匹配，另有游戏程序集字面量可提供候选。

本次只读检查，没有修改或执行适配包，没有连接游戏。

## 依据

- 检查包：apex.wh40k-rogue-trader.gpack，1.0.0，80 条分组。
- 当前安装 Init.bnk SHA256：2ECC1EE501C593DE81E2616CC9B89AEE025DA5B3C3578ACEFC0447DD8C5133F9，与包中记录一致。
- 实际块：BKHD、INIT、STMG、HIRC、ENVS、PLAT；无 STID 块。HIRC 中核对到 80 个 type 8 总线对象。
- 游戏文件清单中未发现 SoundBanksInfo.xml/json、Wwise_IDs.h 等常见名称配套文件；ProjectInfo.xml 仅有项目、平台、语言与生成器信息。未穷尽解包所有 Unity 资产，不能据此证明发布文件任何地方都没有名字。
- 48 个常见名称候选产生 6 个当前总线 ID 匹配。针对 5 个游戏程序集的 #US 用户字符串检查，新增 InteractiveObjects 候选，另匹配 UI/ui。

## 匹配结果

| 包中标签 | 名称候选 | 当前银行总线 ID |
|---|---|---|
| 主输出总线 | Master Audio Bus | 3803692087 |
| A15 | Music | 3991942870 |
| A4-22 | Dialogue | 3930136735 |
| A1 | Ambience | 85412153 |
| A6 | UI | 1551306167 |
| A13 | Video | 2982943478 |
| A4-18 | InteractiveObjects | 3614659429 |

候选均按 Wwise FNV-1（ASCII 大小写归一）算出 ID，并与本机 Init.bnk 的总线对象核对。InteractiveObjects 和 UI/ui 也确实出现在 Code.dll 的用户字符串中；未进一步证明这些字符串的调用点就是总线访问。

匹配不等于数学意义上还原唯一原名：32 位哈希存在碰撞，大小写不能唯一恢复，实际总线还可能包含子组或共享处理后的声音。包 README 对 A15 持续音乐的观察与 Music 候选相互支持，但本次未新增场景试听，不把其他候选写成已确认用途。不保证 80 条全部能恢复。

## 继续补名字的方法

无需重做采集模块。使用开发包已有的 tools/Metadata/name_candidates.py，对当前 game.json 与有限名称表运行匹配；候选还可来自游戏程序集、资源对象名和可核对的公开资料。保留编号、候选来源和多候选冲突，试听后再确认语义。

示例命令（路径换为当前开发目录）：

```powershell
python tools/Metadata/name_candidates.py --definition gamepacks/wh40k-rogue-trader/game.json --candidates evidence/names.txt --output evidence/name-candidates.json
```

names.txt 每行一个候选名。工具不会自动改包。未恢复的条目继续保留编号，而不是随意命名。

实现依据及碰撞说明：[wwiser 作者文档：Names](https://github.com/bnnm/wwiser/blob/master/doc/WWISER.md#name-list-and-reversing-names)。它明确列出名称配套文件、从游戏字符串提出候选以及哈希碰撞的限制。

原始核对数据：name-check.json、managed-string-matches.json。仅保存在本地研究目录，不纳入通用开发包。
